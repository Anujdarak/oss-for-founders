# Project implementation guide

Open-source discovery site for startup founders. Free, no login, no paywall, no billing
category, no paid APIs.

## Stack

Next.js App Router, TypeScript, Tailwind, shadcn/ui, Fuse.js, Lucide icons. No backend or
database in V1. Data in `/data/repos.json`.

## Design

No gradients, glassmorphism, glow, or emoji icons. Neutral palette plus ONE restrained accent.
1px borders, not heavy shadows. One sans (Geist) plus one mono (Geist Mono) for stats and tags.
Left-aligned, dense, developer-tool feel like Linear or Vercel docs. Plain specific copy, no
hype words. No fake content. Light and dark mode, visible focus states, 150ms transitions.

## Rules

Never fabricate repos or stats. A chatbox will be added in Stage 4 using weighted retrieval over
`repos.json`.

Work in plan mode first. Run lint and build after finishing. Commit at the end. Don't start the
next stage unprompted.

## Implementation notes

These are facts about the current codebase that are easy to get wrong:

- **Next.js 16.4** with `cacheComponents: true` and `partialPrefetching: true`. This is PPR by
  default. Do not read `cookies()` or `headers()` in the root layout — it forces every segment
  under it to render dynamically. The theme is therefore stored in `localStorage`, not a cookie.
- **Tailwind v4 is wired through a Turbopack loader** (`@tailwindcss/turbopack` in
  `next.config.ts`), not PostCSS. There is deliberately no `postcss.config.mjs`. Don't add one.
- **Next ships its own docs** at `node_modules/next/dist/docs/`. This major version has breaking
  changes relative to most training data — read those docs rather than assuming Next 14/15 APIs.
  `AGENTS.md` is regenerated by `next dev`; commit it rather than deleting it.
- **shadcn/ui is the `radix-nova` style** with the unified `radix-ui` package (not
  `@radix-ui/react-*`) and `cn` from the `cn` package (not `clsx` + `tailwind-merge`).
- The accent lives on `--primary` and `--ring`. `--accent` is shadcn's neutral *hover* token —
  repurposing it would tint every hover state.
- `Badge` is for status/meta (Editor's Pick, difficulty, self-hostable). `Tag` is for taxonomy
  keywords and is mono. Keep that split.
- Tailwind's default transition duration is already 150ms, so `transition-colors` satisfies the
  design rule without an explicit `duration-150`.
- **Do not run `npm audit fix --force`.** It downgrades `shadcn` from 4.x to 1.0.0, which is a
  breaking change. The `overrides.minimatch` pin in `package.json` is deliberate: it clears the
  moderate ReDoS advisory in `ts-morph` and `typescript-eslint` without touching shadcn. Removing
  it brings those back.
- The remaining 3 low-severity advisories are `deepmerge` reached through the shadcn CLI. They
  have **no upstream fix** — the advisory covers `>=4.2.0` and `4.3.1` is the latest release — so
  they stay until shadcn drops the dependency. It is build tooling, not shipped to the browser.
- Header nav links are visible at every width on purpose. They were `hidden sm:flex`, which left
  phones with no navigation at all.

### Added in Stage 2

- **The no-star-counts rule was deliberately reversed.** Stage 1 said the schema had no field for
  star counts because "a number committed to JSON is wrong the next day". Stage 2 commits real
  stats, so the rule became: stats may only ship **inside the `stats` object, which requires
  `fetchedAt`**. The number is still wrong the next day; the timestamp is what makes it honest.
  Never add a stat field outside that object.
- **`review` tracks editorial review, not which file an entry came from.** `editor-reviewed` means
  a human wrote `whyFounders`/`pros`/`cons`; `auto-discovered` means the content came from the
  GitHub API. Most entries in `repos.json` are `auto-discovered` — that file is "hand-picked", not
  "hand-written". The validator fails an `editor-reviewed` entry with no `whyFounders`.
- **Nothing in a prerendered path may read the clock.** Under Cache Components `Date.now()` and
  `new Date()` *throw a build error* during prerender. That is why "possibly stale" is computed as
  `pushedAt` vs `stats.fetchedAt` (both in the data) rather than against now, and why dates render
  absolute ("updated Oct 2026") instead of "3 days ago". `lib/format.ts` is clock-free by contract.
- **`params` is awaited at the top of `/c/[slug]` and `/r/[id]`, not inside `<Suspense>`.** The
  docs suggest awaiting it inside the boundary, but that flushes the shell before the slug is
  known, so `notFound()` answers **HTTP 200 with not-found markup**. Both routes enumerate their
  full param space in `generateStaticParams`, so awaiting at the top costs no prerendering.
  `searchParams` (`?page=`) genuinely cannot be known at build time and stays inside the boundary.
- **`lib/categories.ts` must stay React-free.** `scripts/validate-repos.ts` imports the schema,
  which imports the categories, and it runs on plain tsx. Category icons live in
  `components/category-icon.tsx` for that reason.
- `data/discovered.json` is committed as `[]`. A static import of a missing file is a build error,
  so the file has to exist for the merge in `lib/data` to be live code.
- Descriptions are quoted verbatim from GitHub with one normalization: decorative emoji are
  stripped (® ™ © are kept). A leading 🤗 in a card title is emoji-as-iconography, which the
  design rules ban.
